# Pure Caustic Orb Proof Design

Date: 2026-04-18
Status: Approved direction, proof implementation in progress

## Summary

Build a theorem-grade analytical specification and a reproducible Rust proof
harness for a pure caustic orb code. The payload is carried by the optical
field of a fixed shell orb, not by a QR code, ring code, or separate geometry.

This effort is not a production claim of QR-level robustness. It is a
formalized analytical model with explicit assumptions, a deterministic encoder,
a two-stage decoder, and a proof artifact that either supports the design
within its assumptions or shows where the assumptions fail.

## Chosen Constraints

The user-selected design constraints are:

- pure caustic orb
- analytical decoder
- 64-bit public ID
- 128-bit internal codeword after ECC and checksum expansion
- fixed optical shell
- whole optical field observable
- luma-first decoding
- reliably segmentable orb boundary
- canonical orientation allowed
- reserved orientation subspace with an azimuthal phase notch
- localized spherical wavelet payload basis
- continuous codebook in coefficient space
- hybrid packing objective across coefficient and rendered-image space
- two-stage decoder
- probabilistic error bound
- full stochastic camera model
- factorized parametric family

## Non-goals

- claiming QR-equivalent robustness under completely arbitrary backgrounds
- learned decoder or learned pose estimation
- product-grade iOS integration in this phase
- rendering polished marketing visuals
- full URL payloads
- worst-case guarantees against unconstrained perturbations

## Object Definition

### Public message

Let the public identifier be:

`m ∈ {0,1}^64`

This is the user-visible or application-visible ID.

### Internal codeword

The encoder maps `m` to a 128-bit internal codeword:

`u = E(m) ∈ {0,1}^128`

where:

- the first 64 bits are the public message
- a cryptographic checksum is appended
- the remaining redundancy is parity or error-correcting structure

The exact ECC family is not fixed by the user selections. The proof harness may
use a deterministic linear parity construction plus a truncated cryptographic
checksum, as long as the codeword is exactly 128 bits and the mapping is
deterministic.

## Functional Decomposition

The encoded optical field is split into orthogonal parts:

`f = f_orient + f_payload`

with:

- `f_orient ∈ V_orient`
- `f_payload ∈ V_payload`
- `V_orient ⟂ V_payload`

The orientation field carries a faint azimuthal phase notch. The payload field
carries the internal codeword through a localized spherical wavelet frame.

The decoder is allowed to use the whole observed optical field, but the proof
depends on this subspace separation.

## Basis Construction

### Orientation subspace

`V_orient` is a reserved low-dimensional subspace containing only orientation
features. It is generated from a fixed azimuthal phase notch family, such as:

`g_k(θ, φ) = a_k(θ) cos(kφ + φ₀)`

with the actual implementation choosing a finite basis and orthogonalizing it
against the payload frame.

### Payload subspace

`V_payload` is generated by a localized spherical wavelet frame:

`Ψ = {ψ₁, ψ₂, ..., ψ_N}`

The implementation may use a deterministic localized spherical construction
that behaves as a wavelet frame on sampled sphere points. Exact closed-form
wavelet family choice is secondary to the following requirements:

- localization on the sphere
- multiple spatial scales
- numerically stable frame operator on the sampled sphere
- explicit orthogonalization against `V_orient`

## Continuous Codebook

The user selected a continuous codebook rather than sign-only coefficients.
This means the internal codeword is embedded into a continuous coefficient
vector:

`a(u) ∈ ℝ^N`

The proof harness will realize this by:

1. mapping the codeword into a deterministic real embedding
2. applying a fixed packing operator
3. constraining the result to lie in `V_payload`

The codebook is therefore a finite subset of a continuous coefficient space.

## Fixed Optical Shell Model

The forward model is:

`y = H(θ_cam, λ_cam, f_orient + f_payload) + ε`

where:

- `H` is the known fixed-shell optical transport and capture operator
- `θ_cam` are geometric camera variables
- `λ_cam` are photometric and degradation variables
- `ε` is residual image-space perturbation

The proof harness will use a simplified analytical shell model that preserves
the key structure needed for proof:

- fixed shell
- known pose action on the encoded field
- known luma observation operator
- blur and exposure applied in the image formation chain

This is sufficient for theorem-grade analysis. It is not a claim that the full
physics of real glass have been solved in closed form.

## Camera Model

The probability model is over a factorized stochastic camera family:

`P = P_pose × P_blur × P_exposure × P_white × P_compression × P_segment × P_residual`

The analytical implementation is allowed to simplify the luma-first channel by
folding white-balance into intensity scaling or omission, provided the proof
states that luma is primary and color is secondary.

The proof harness must state exact parameter ranges and distributions.

## Decoder

The decoder is two-stage.

### Stage 1

1. segment the orb boundary
2. recover orientation from `V_orient`
3. project the normalized observation into coefficient space
4. produce a shortlist using coefficient-space distance

### Stage 2

5. re-render each shortlist candidate through the fixed shell model
6. score candidates in rendered-image space
7. choose the maximum-score candidate
8. validate checksum and ECC structure

This is an analytical decoder. No learned model is allowed in the proof phase.

## Theorem Target

The target guarantee is probabilistic, not deterministic.

Let the true public ID be `m`, internal codeword `u = E(m)`, and decoded output
`m_hat`.

The desired theorem has the form:

`P[m_hat ≠ m] ≤ B(Δ_coeff, Δ_img, Σ_cam, shortlist_size, decoder_params)`

where:

- `Δ_coeff` is a lower bound on codeword separation in coefficient space
- `Δ_img` is a lower bound on rendered-image separation after the fixed shell
- `Σ_cam` or equivalent parameter set describes the factorized stochastic camera
  family
- `B` is an explicit upper bound derived from the model

The proof harness is expected to instantiate a concrete bound under the chosen
model assumptions. The harness does not need to prove a universally optimal
bound.

## Proof Obligations

The implementation is not allowed to hand-wave. It must establish, by proof or
reproducible numerical certification, the following:

1. `V_orient ⟂ V_payload` up to a stated tolerance on the sampled sphere
2. the payload frame has a stable frame operator or equivalent lower/upper
   bounds
3. the encoder from `u` to `a(u)` is injective on the chosen finite message set
4. the codebook has a computable coefficient-space separation bound
5. the rendered-image operator preserves a nontrivial fraction of that
   separation over the bounded camera family
6. the stage-1 shortlist contains the true codeword with high probability under
   the stated model
7. the stage-2 rescorer admits an explicit error bound or an explicit certified
   empirical upper bound under the simulator assumptions

## What Counts As “Proved”

For this phase, “proved” means:

- the model assumptions are explicit
- the theorem statement is explicit
- the code constructs the spaces and codebook deterministically
- the code computes the quantities used in the theorem
- tests verify the structural claims
- the proof harness emits a report with the resulting bounds

This phase does not claim proof against real-world unconstrained photos. It
claims proof only inside the model and parameter family defined here.

## Deliverables

- theorem-grade spec document
- implementation plan
- Rust proof modules and tests
- Rust binary or command that generates a proof report
- updated crate documentation

## Finish Criteria

The work is complete only if all of the following are true:

- the theorem-grade spec is written and internally consistent
- the implementation plan exists and matches the spec
- failing tests are written first for the structural claims
- the Rust harness computes orthogonality, frame stability, codeword separation,
  and error-bound inputs
- fresh verification commands pass
- the proof report is generated from the current code and included in the final
  handoff
